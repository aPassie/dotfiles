# Guide for Claude Code

This repository is the source of truth for a desktop that took many design rounds to build.
When asked to set the system up again, **restore from these files; do not redesign or
rewrite anything.** When asked to change the desktop, change the live files under `$HOME`,
verify, then run `tools/sync-from-home.sh` and commit.

## Restoring on a fresh Arch install

1. Install packages: `sudo pacman -S --needed - < packages/pacman.txt`, then
   `yay -S --needed - < packages/aur.txt` (install `yay` or `paru` first). The user runs
   `sudo` commands themselves.
2. `./install.sh --dry-run`, then `./install.sh`. It copies `.config` and `.local` into `$HOME`
   (replaced files go to `~/.dotfiles-backup-<date>`), rewrites `/home/shanks` to the new home
   path, builds Dolphin's shim, enables the user services and merges the Claude hooks.
3. Do the manual steps the script prints: SF Pro font, wallpaper, lock-screen image, weather
   city, `fisher update`.
4. Only on the same laptop (Lenovo Legion Slim 5 16APH8): install `system/` by hand. Each file
   sits at its real path under `system/` (`system/etc/...`, `system/usr/local/...`). Read
   "Hardware files" below first.
5. Verify (next section) before telling the user it is done.

## Verifying

- `niri validate` must say the config is valid.
- `qs -c ii log | grep -E 'Configuration Loaded|Failed to load' | tail -1` must end in
  "Configuration Loaded". On failure the shell silently keeps running the previous version.
- `glass-doctor --full` must report no PROBLEM lines.
- Open each panel without the pointer and capture it with `grim`:
  `qs -c ii ipc call glassPanels toggle <wifi|bluetooth|notifications|control|claude>`,
  `glassPanels detail <sound|mic|night|displays|awake|dgpu|power>`,
  `glassPanels peek <battery|weather|monitor|wifi|bluetooth|notifications>` (`peek ""` to release),
  `launcher toggle`, `launcher clipboard`, `mediaControls toggle`, `appStrip menu <app name>`.
- Dolphin: `dolphin-macos` must open black, with round toolbar buttons and a
  "Home › Downloads" breadcrumb.

## Map of the desktop

### niri (`.config/niri/`)
`config.kdl` only includes `config.d/*.kdl`. `30-window-rules.kdl` ends with the blur rules the
glass panels depend on (layer namespaces `quickshell:glass` and `quickshell:popup`,
`background-effect { xray false }`). `95-monitors.kdl` is generated by
`~/.local/bin/niri-display-mode` (niri cannot mirror; modes are Extend / Laptop only /
External only). Some files in `config.d` are owned by root on the original machine.

### Glass shell (`.config/quickshell/ii/`)
Started by niri: `qs -c ii --no-duplicate`. Entry is `shell.qml`, which loads
`panelFamilies/IllogicalImpulseFamily.qml`; that file lists every window the shell creates.

- `modules/ii/glassbar/GlassBar.qml`, `GlassBarContent.qml`: the bar and all its islands.
- `GlassIsland.qml` + `shaders/island.v3.frag.qsb`: one island. It refracts a cached strip of
  the wallpaper; nothing live is captured.
- `AppStrip.qml`: the app island (open apps per workspace, tray-only apps as a last group,
  magnification, right-click menu through `GlassAppMenu.qml`).
- `GlassPanel.qml`: frame for drop-down panels. `services/GlassPanels.qml` holds which panel is
  open and the IPC handlers used for testing.
- `GlassControlCentre.qml`, `GlassControlDetails.qml`: Control Centre and its detail pages,
  including the Power page (lock, sleep, restart, shut down).
- `GlassLauncherPanel.qml`: app launcher and clipboard picker.
- `services/ClaudeStatus.qml` + `GlassClaudePanel.qml` + `GlassClaudeNotice.qml`: the Claude
  island. Claude Code hooks run `~/.local/bin/claude-status-hook`, which writes one JSON file
  per session to `~/.local/state/claude-status/`; the shell reads them through
  `claude-status-list`. The hook must print nothing.
- `services/GlassBackdrop.qml`: finds the wallpaper swaybg is showing and derives the tint.
- `services/Niri.qml`: windows, workspaces, focus, from `niri msg --json event-stream`.
- `modules/ii/lock/`: the shell's own lock surface (old Material look). Daily locking uses
  hyprlock.

Shaders are compiled with `/usr/lib/qt6/bin/qsb --qt6 -o x.frag.qsb x.frag`. Qt caches
compiled shaders by file name, so after recompiling give the `.qsb` a new name
(`island.v3` → `island.v4`) and update the reference.

### Dolphin (`.config/dolphin-macos/`)
`~/.local/bin/dolphin-macos` sets `XDG_CONFIG_HOME` to this folder so Dolphin's theme cannot
clash with other Qt apps, then starts Dolphin with Kvantum, a stylesheet and a preload library:

- `Kvantum/GlassSolid/`: black theme, fill-only selection.
- `glass.qss`: round toolbar buttons, the path "pill", tabs, status chip.
- `glass-shim/glass-shim.cpp` → `glass-shim.so` (`build.sh`): draws the breadcrumb over
  `KUrlNavigator`, swaps toolbar icons for SF Symbols, fixes a spacer Dolphin sizes in code.
- `~/.local/share/kxmlgui5/dolphin/dolphinui.rc`: toolbar layout. Its `version` is 9999 on
  purpose: Dolphin ignores the file when its built-in copy has a higher number.
- `dolphin-warm.service` keeps one Dolphin running so windows open fast. The local
  `org.freedesktop.FileManager1.service` makes "show in folder" open this Dolphin.

Programs started from Dolphin inherit its `XDG_CONFIG_HOME` and create stray config folders
inside `dolphin-macos`.

### Qt and GTK apps
Style is Darkly with the `GlassBlack` colours in `~/.config/kdeglobals` (`[KDE] contrast=0`
keeps tab strips dark). GTK takes its colours from `gtk-3.0/gtk.css` and `gtk-4.0/gtk.css`.
`environment.d/50-qt-theme.conf` gives the same Qt settings to D-Bus-started programs such as
the KDE file picker.

### Portals (`.config/xdg-desktop-portal/niri-portals.conf`)
File picker, app chooser and access dialogs use the KDE backend; screen sharing and
screenshots must stay on the GNOME backend (the KDE one does not work on niri).

### Update protection
`glass-doctor` (triggered by `glass-doctor.path` on `/var/lib/pacman/local` and at login) and
`glass-snapshot` (local git history, path list inside the script, extra private paths in
`~/.config/glass-snapshot-extra.txt`). Add new custom files to the snapshot list and to
`tools/sync-from-home.sh`.

### Dictation (hold Right Ctrl)
xremap (`.config/xremap/config.yml`) turns Right Ctrl press/release into `~/.local/bin/ptt
down|up`, which writes to a FIFO read by `~/.local/share/ptt/pttd.py` (`pttd.service`); the
text is typed with `wtype` on release. Only `pttd.py` is in the repository. To set it up:
`uv venv ~/.local/share/ptt/.venv`, install the `moondream` package into it, then replace the
CUDA build of torch with the CPU build from the PyTorch CPU index and uninstall the `nvidia-*`,
`cuda-*` and `triton` packages (6 GB down to about 1.6 GB). Run the daemon once with network
access so the "moondream/parakeet-redux" model downloads (the unit sets `HF_HUB_OFFLINE=1`),
then `systemctl --user enable --now pttd.service`. xremap does not reload its config on
change: `systemctl --user restart xremap`.

### Hardware files (`system/`)
For a Legion Slim 5 16APH8 (Ryzen 7840HS + RTX 4060). The NVIDIA card is powered off at boot
and switched on only on demand:

- `usr/local/sbin/disable-nvidia-dgpu.sh` + `disable-nvidia-dgpu.service`: power the card off.
- `dgpu-compute.service`, `dgpu-display.service` and the `dgpu-*` scripts: turn it on for CUDA
  or for an external display, and off again.
- `etc/modprobe.d/nvidia-no-autoload.conf`: stops the driver loading at boot. Without it the
  power-off can deadlock against TLP during boot and the login screen never appears.
- `etc/udev/rules.d/99-rapl-readable.rules`: lets the battery pop-up read power draw.
- `etc/tlp.d/01-shanks-battery.conf`, `etc/modprobe.d/mt7921e*.conf`.
- `etc/sddm.conf` selects the login theme "silent", which is not a package: it comes from the
  SilentSDDM project and must be installed to `/usr/share/sddm/themes/silent` first. Without
  it, leave this file out and SDDM uses its default theme.

Enable with `sudo systemctl enable disable-nvidia-dgpu.service` (the other units are started on demand). The
polkit rule that lets the shell start the dGPU services without a password is not in this
repository (not readable); recreate it if the Control Centre's dGPU switch asks for a password.

## Design rules the user has already decided

Do not reopen these unless asked.

- Clear glass, not frosted. Panels are see-through tinted glass with a light blur behind and a
  thin rim. No refraction, colour dispersion, glow or heavy blur on panels.
- Islands use the original simple shader with an even white rim.
- Inside Dolphin: fills only, no bright rims; square window corners; pitch black.
- Bar font is Outfit, 14 px. Symbols are SF Symbols addressed by code point from the SF Pro
  font; other icons are WhiteSur.
- App island: no dots under icons, no dimming, no focus highlight. Background apps sit after a
  divider at full strength.
- Panels close only after the pointer has left them.
- The media island must not disappear when the app island grows; the centre group slides left.
- Mock-up first for any new UI: write a local `.html` file, get approval, then build.

## Rules for working on the live desktop

- Never trigger restart, shut down, log out, sleep, forget-network, dGPU or display-mode
  controls while testing. A test shell acts on the real system. Use the IPC commands above and
  `grim` instead of clicking.
- Never lock the session to test the lock screen, and never test wrong passwords: the system
  locks the account after three failures.
- Quickshell hot-reloads when a file changes, but not after `sed -i` (it replaces the file).
  Write files in place, then compare the number of "Reloading configuration" lines in
  `qs -c ii log`; `touch` the file if it did not reload.
- A new inline `component X: ...` can fail on hot reload with "X is not a type"; put new
  components in their own file.
- Never use a scaled or animated item as the `Region` item of a window's input mask.
- `ScreencopyView` crashes the shell on this Qt version; do not use it.
- `pkill -f` / `pgrep -f` also match the shell running the command when the pattern appears
  anywhere in that command line. Kill test programs by PID.
- Do not touch the user's open Dolphin windows. To look at a change, open an extra window with
  `dolphin-macos --new-window`, or run Dolphin with `QT_QPA_PLATFORM=offscreen`.
- Commits and anything published carry no AI attribution.
